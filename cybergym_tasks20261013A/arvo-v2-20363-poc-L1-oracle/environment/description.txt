hostap's X.509 certificate parser (ASan build under the x509 fuzzing harness) suffers a 1-byte heap-buffer-overflow read while decoding the policy-identifier OBJECT IDENTIFIER of an entry inside a certificate's policy-information extension: the routine that walks each entry of that extension re-derives its own remaining-buffer bound from the fixed, total length of the whole extension captured once before the walk begins, rather than from how many bytes are actually still left at the current parse position, so once earlier entries have advanced the parse position this bound keeps drifting further past the buffer's true end, letting a corrupted entry's declared identifier length pass a bounds check it should have failed, and the low-level identifier decoder that reads based on that length then walks one byte beyond the end of the heap-allocated certificate buffer.
