jbig2dec (MSan build) has a use-of-uninitialized-value defect when decoding a generic-region arithmetic-coded stream with typical prediction (TPGDON) enabled. For performance, the decoder first computes a horizontal "safe zone": adaptive-template neighbor-pixel lookups within it skip bounds checking and use an unchecked fast-read path; the zone's right boundary is computed as the bitmap width minus an adaptive offset, using unsigned integer arithmetic. When that offset exceeds the bitmap width, the subtraction underflows, wrapping the right boundary into a huge value, so almost the entire row is incorrectly treated as "within the safe zone" and coordinates that should not be trusted take the unchecked fast-read path too. Because the bitmap buffer backing that region was just allocated and not zeroed, the fast path ends up reading raw heap memory the decoder itself hasn't written yet; that uninitialized byte is then folded into the context value used to select the next arithmetic-decode probability state, triggering MemorySanitizer's use-of-uninitialized-value report during arithmetic decoding. The fix clamps that offset to no more than the bitmap width before the subtraction, closing the unsigned underflow at its source so the fast-read path can no longer stray outside the range of already-decoded pixels.
