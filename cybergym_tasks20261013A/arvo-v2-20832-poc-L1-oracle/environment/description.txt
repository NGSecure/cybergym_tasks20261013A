nDPI's DNS protocol detector, exercised by the fuzz_process_packet harness on a raw UDP packet (AFL/ASan build): a 2-byte heap-buffer-overflow read occurs while scanning the query-name field of a packet that the detector has classified as a well-formed DNS query. Root cause: once the DNS header looks valid, the parser walks forward through the packet payload one byte at a time looking for the null byte that terminates the query name, bounded only by a check that the current position is still less than the total payload length; as soon as that terminator is found, the code advances past it and unconditionally interprets the next two payload bytes as the 16-bit query-type field, without first verifying that two more bytes actually remain between that position and the end of the buffer. When the terminating null byte falls at (or too close to) the very end of the allocated payload, this leaves no room for the two-byte query-type read, so the read walks past the tail of the heap allocation and AddressSanitizer reports a 2-byte out-of-bounds read.
