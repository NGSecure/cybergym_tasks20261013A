When WavPack decodes DSD audio in its "fast" mode, it maintains a per-history-bin cumulative probability table stored as a signed 16-bit type; since 256 accumulated 8-bit probability values can exceed the signed 16-bit positive range, the accumulated sum wraps around into a negative value. The main decode loop then uses this value, which is meant to be an upper bound for the bin, to bounds-check a freshly decoded index — but because the comparison is unsigned, the negative value is treated as a huge unsigned number, so an out-of-range index that should have been rejected passes the check. The program then uses this runaway index to look up a fixed-capacity per-bin symbol table, reading far outside its allocation into unmapped memory, triggering a MemorySanitizer wild-pointer SEGV (read). The fix changes the cumulative probability table's storage type from signed to unsigned 16-bit, so the maximum legitimate accumulated value no longer wraps negative and the bounds check works as intended.
