c-ares's DNS SOA-record reply parser frees a heap-allocated resource-record owner-name buffer while looping over the answer records of a response, but never resets the pointer to NULL afterward, and the same variable is reused as the output argument when expanding the name of the next record in the loop. Root cause: the underlying name-decompression helper leaves its output pointer completely untouched whenever it fails early (for example on a malformed/invalid compressed label), so if a later iteration's name expansion fails, the error-handling cleanup frees the pointer again while it still holds the stale value left over from the previous iteration's already-completed free, resulting in a heap double-free on the same allocation.
