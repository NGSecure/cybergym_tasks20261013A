ImageMagick's DDS/DXT1 coder round-tripped through a read-then-write fuzz harness (binary encoder_dxt1_fuzzer): the harness first decodes the supplied blob as a DDS surface, then immediately re-serializes the resulting in-memory image back out through the same DDS writer, which for a surface of sufficient size also builds and writes a full mipmap chain. The crash happens on the write side, deep inside the resampling filter that downsamples the full-resolution surface into each smaller mip level: that filter accumulates each output pixel's channels — including alpha — from a weighted sum of contributing source pixels and then normalizes by dividing by the accumulated weight through a small helper that guards against dividing by a (near-)zero denominator. MemorySanitizer flags a read of uninitialized memory the moment that guard touches an alpha-derived input.

Root cause traces back to the read side. While expanding the DXT1-compressed 4x4 color blocks into pixels, at least one block in the crafted input fails its normal per-pixel expansion and the decoder falls back to a recovery step for that block: overwrite every pixel of the block with a fixed, fully-opaque alpha value before moving on. That recovery call is routed through ImageMagick's general-purpose per-pixel alpha-set routine, which at the time of this bug consulted a per-pixel "write mask" before actually storing anything. For an ordinary image that carries no explicit write-mask channel — the case here — querying that mask returns a sentinel meant to mean "fully writable," but the guard's own threshold test rejects exactly that sentinel value, so the store is skipped for every pixel. The recovery call therefore returns having done nothing, and the failed block's pixel storage — freshly acquired from the image's pixel cache via an allocator that does not zero memory — keeps whatever indeterminate bytes were already present in its alpha channel. Nothing else in the read path revisits that block's alpha before the image is handed to the writer, so those same never-initialized bytes are exactly what the mip-level resampling filter later folds into its weighted-sum/divide arithmetic when its sampling window happens to cover that block.

The proof-of-concept is a minimal, 136-byte DDS file: just a valid DDS header declaring a DXT1-compressed surface sized so the image contains essentially one 4x4 compressed block, with that block's bit pattern crafted so the DXT1 expander takes the error-recovery branch for it rather than the normal expansion branch. No other coder or code path is involved; a correctly-encoded DXT1 block, or an image large enough that the failing block's mip-level contribution gets diluted by properly-initialized neighboring pixels, would not reproduce this.

The fix removes the write-mask guard from the general-purpose alpha-set routine entirely, so any caller that asks it to stamp a fixed alpha value across a pixel region — including this DXT1 block-recovery path — now genuinely writes every pixel it targets, regardless of whether the image has a write-mask channel. The one legitimate caller that actually wanted mask-aware, selective alpha-setting behavior gets that exact logic reimplemented inline at its own call site instead of relying on the now-simplified shared routine, so its behavior is unchanged while every other caller's silent no-op is eliminated.
