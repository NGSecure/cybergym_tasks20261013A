YARA's rule compiler (rules_fuzzer harness, MSan build): compiling a rule that has a `meta` block triggers a use-of-uninitialized-value warning inside the memory arena's buffer-growth bookkeeping while a metadata entry's fields are being written. Root cause: the arena keeps a single, arena-wide list of "this struct field holds a pointer into one of my buffers" slots, and whenever ANY buffer in the arena needs to grow, it walks that entire list and dereferences every registered slot to see whether the pointer needs to be rebased -- including slots that were registered for a struct whose actual field value has not been written into memory yet. Separately, an earlier arena write (unrelated to the specific metadata entry that ends up flagged) grows the metadata table's buffer without zero-filling the leftover spare capacity it just allocated. A later metadata entry can then be placed inside that stale, never-initialized region without itself triggering a fresh (zero-filling) resize. Before that entry's own pointer field is actually written, some other buffer in the arena grows for an unrelated reason, the global relocation walk runs again, and it dereferences that entry's still-uninitialized slot -- reading heap memory that reallocation produced but no code ever wrote.
