GDAL's bundled libtiff library implements a CCITT Group 4 (T.6) two-dimensional bitonal/fax decompressor that libtiff invokes whenever a TIFF strip's Compression and PhotometricInterpretation tags mark it as fax-encoded bi-level image data. While decoding an encoded row, the decompressor walks the row and records each pixel color transition ("changing element") into a pair of fixed-capacity per-row buffers whose size was fixed once, when the strip's row geometry was first set up from the TIFF's declared image width. After stepping through all the transitions the decoder actually finds, it performs one further, unconditional write to close out the row's transition list. A row whose Group-4 encoding is crafted to yield more transitions than the declared image width would normally produce can exhaust that fixed capacity before this final write executes, so the closing write lands past the end of the allocated buffer, producing a small out-of-bounds heap write.

In this crash the overflow is reached through GDAL's ordinary bulk block/strip raster-read path: the raster band implementation handling this file's bit depth requests a whole encoded strip in one call through libtiff's standard strip-reading entry point, which in turn invokes the fax decompressor on the crafted strip content before the pixel data is checksummed.
