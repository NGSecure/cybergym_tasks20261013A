Compiling a specific 8-bit pattern makes PCRE2's pattern-analysis pass corrupt heap memory just past a small fixed-size bitmap embedded in the compiled-pattern object, and that corruption later causes an unrelated bytecode-scanning routine to dereference a bogus pointer, which AddressSanitizer reports as a heap-buffer-overflow read.

Root cause: when a pattern is compiled with case-insensitive matching plus Unicode property support enabled, but without full UTF interpretation, one helper computes the alternate-case code point of a character via the Unicode case-folding table and sets the matching bit in the pattern's built-in "possible starting code unit" bitmap. That bitmap only has 256 slots, but the code path taken in this mode does not clamp or range-check the alternate-case value before using it as the bit index, so an alternate-case value above 255 makes the write land outside the bitmap and stomp on adjacent bytes belonging to the same heap block as the compiled pattern.

Those clobbered bytes are not read immediately. A later, logically separate stage walks the freshly compiled instruction stream to figure out which byte(s) a match could legitimately start with; while skipping over bracketed groups and alternatives it reads small integer offsets directly out of the instruction stream and adds them to its scan pointer to jump to the next alternative/instruction. If the earlier out-of-bounds write happened to land on bytes this walker later treats as one of those offsets, the walker computes and dereferences a wild pointer built from corrupted data, which is what the sanitizer actually catches — several function calls and, from the crash site's point of view, an unrelated code path away from where the real out-of-bounds write occurred.

So the reported crash location is a downstream symptom, not the root cause: the true bug is a missing bounds check on a Unicode alternate-case value before it is used to index a fixed-size 256-bit bitmap during pattern compilation, in a caseless + Unicode-property (non-UTF) code path.
