PHP's mbstring extension, when compiling a user-supplied regular expression through its bundled Oniguruma regex engine, processes each look-behind assertion by first working out whether the assertion's body is guaranteed to match zero characters; when it is, the compiler takes a shortcut and discards the body's parsed subtree outright, replacing the look-behind with a trivial always-fails (or always-succeeds) node, on the assumption that nothing else in the pattern still needs that subtree. This assumption breaks when the look-behind's body includes a capturing group that the pattern also invokes elsewhere as a named or numbered subroutine call: the discard step frees the group's subtree without checking for that outside reference, leaving the subroutine-call node pointing at freed memory. Compilation also validates, separately for each look-behind assertion in the pattern, which node types are legal inside a look-behind's body, recursing through the assertion's contents and, when it reaches a subroutine call, following that same pointer into the referenced group's body to keep validating; if a different, earlier-processed look-behind elsewhere in the same pattern already triggered the discard step on that referenced group, this later look-behind's own validation walk dereferences the resulting freed memory while checking its own, unrelated body. AddressSanitizer flags the read the moment a pattern contains two look-behind assertions, where one has a zero-width body containing a capturing group that is also invoked as a subroutine call from inside the other.
