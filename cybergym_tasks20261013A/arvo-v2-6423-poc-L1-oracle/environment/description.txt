Wireshark's SigComp/UDVM bytecode interpreter decodes "reference" operands against a fixed 64KB scratch memory buffer, and one of its three operand-encoding branches (the form that spells the target address out directly as two raw bytes) advances the already range-checked instruction offset by one *before* re-validating it and then immediately uses that unchecked offset to index the buffer, so an operand instruction positioned exactly at the last valid offset pushes the index one past the buffer's end and the very next byte read lands one byte outside it. The upstream commit does not touch this decode routine or add any bounds re-check at all — instead it flips the module preference that gates whether SigComp payloads get UDVM-decompressed in the first place (plus a sibling preference gating whether the UDVM bytecode itself gets dissected) from enabled to disabled by default, so the call chain leading into the decode routine is simply never entered during ordinary dissection anymore; the differential holds because the fixed build takes an early preference-gated bail-out several call frames above the buggy code, not because the underlying off-by-one was patched.
