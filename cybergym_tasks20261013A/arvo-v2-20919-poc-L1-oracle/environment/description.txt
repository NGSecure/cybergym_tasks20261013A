HarfBuzz's glyph outline-drawing pipeline for OpenType variable fonts (glyph variation data) computes, for each font axis, an interpolation scalar from a tuple-variation record's per-axis peak values before applying position deltas to the glyph's contour points. While walking a font's chain of tuple-variation records for a given glyph, the code validates that each record's fixed-size header lies within the glyph's variation-data blob, but never validates that the record's own byte extent — the header plus its embedded per-axis peak/start/end value arrays, whose combined length depends on the font's axis count and per-record flags — actually fits inside that same blob. A crafted font can declare an axis count larger than the number of per-axis peak values a given tuple-variation record physically stores. When the interpolation-scalar loop then indexes the peak-value array once per font axis, the lookup for one of the missing axes lands on bytes that remain inside the still-allocated heap buffer backing the glyph's variation data, but that were never actually written when this particular record was deserialized — stale content left over from how that memory was previously used. The moment that never-initialized two-byte value is loaded and then tested in a branch to decide how it should influence the interpolation, MemorySanitizer flags the read as a use of uninitialized memory.
