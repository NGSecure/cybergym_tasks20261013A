open62541's JSON encoder for OPC UA values, when serializing a value that is or embeds an OPC UA DiagnosticInfo, recurses into a chain of nested inner-diagnostic-info structures because that particular builtin type is self-referential (an instance can hold another instance of the same type). Each nesting level pushes one more entry onto a fixed-capacity per-context array that records, for every open bracket depth, whether a comma is needed before the next JSON element; a depth counter guards against exceeding that array's capacity before each new level is entered. Root cause: the guard compares the depth counter against the array's exact declared capacity, but the comparison happens before the counter is incremented for the level about to be opened, and the incremented value is then used directly as the array index. A nesting chain deep enough to reach that capacity value still passes the check on what should have been the last legal level, gets incremented one step past it, and the following array write lands one slot beyond the array's last valid index — an off-by-one boundary condition in the recursion-depth guard rather than an absent bound check. The identical off-by-one pattern (comparing against the raw capacity instead of capacity-minus-one prior to incrementing) also exists in the sibling logic that opens and closes JSON array nesting, and in the corresponding structural-recursion guard on the JSON-parsing/decoding side, since all of these share the same fixed-capacity depth-tracking array.
