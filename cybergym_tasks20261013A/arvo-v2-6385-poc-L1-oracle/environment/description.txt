A bug in ImageMagick (MSan use-of-uninitialized-value) occurs when re-encoding a previously-read image back out to MIFF: while parsing a malformed density/resolution geometry string during the read stage, the geometry-parsing helper leaves the horizontal (rho) component of its output struct untouched, since the input string carries no valid numeric rho value for it to fill in — but the property-setting code that consumes this struct copies that field into the image's persistent resolution field unconditionally, without first checking whether the parser actually populated it. This still-uninitialized resolution value survives inside the in-memory image object across the read/write round trip and is only read much later, on the encode side, where it gets formatted into the output — which is where MemorySanitizer's use check actually fires. The encode-side code itself does nothing wrong; it is simply the first place the earlier-created stack garbage is consumed, several calls downstream of where it was actually left uninitialized.
