A bug in ImageMagick (MSan use-of-uninitialized-value) occurs while decoding a Radiance HDR/XYZE image: the decoder allocates one per-scanline pixel buffer with a raw, non-zeroing heap allocator before the scanline-decoding loop begins, then fills it from the file's run-length-encoded or raw scanline bytes without verifying that a truncated or malformed run actually wrote every byte of the buffer. Processing proceeds regardless, unpacking four channel bytes per pixel out of that buffer and branching on whether the exponent/alpha byte is non-zero to decide whether to apply an exponent-based gamma scale to the pixel — so on a short or malformed scanline, a tail byte the decode loop never wrote is read straight out of the original, uninitialized allocation and used to drive that branch.
