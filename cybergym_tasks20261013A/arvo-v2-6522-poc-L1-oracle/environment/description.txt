MuPDF (pdf_fuzzer, MemorySanitizer build): rendering a page whose (repaired/malformed) image XObject declares a height of 65535 pixels feeds that oversized dimension into the bilinear-interpolation ("lerp") image-painting path, which packs the source pixmap's width/height into a 16.16 fixed-point value to build the per-scanline sample bounds used while stepping across source pixels; because that packing left-shifts the dimension by 16 bits with no upper-bound check beforehand, a dimension this large silently wraps around inside the 32-bit fixed-point value instead of failing safely, so the interpolation sampler ends up trusting a bound that no longer matches the pixmap's real allocated size. It then keeps stepping the source pointer using that wrapped bound and walks past the end of the actual (much smaller) sample buffer, producing an out-of-bounds read there — an oversized-input integer overflow leading to a read past the buffer's real end, not an uninitialized-value bug, and not a write.
