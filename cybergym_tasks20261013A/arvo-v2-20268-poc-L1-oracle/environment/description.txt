Skia's Skottie engine (Lottie/After-Effects JSON animation renderer, skottie_json fuzz target, MSan build) reports a use-of-uninitialized-value inside a trim-path shape effect's offset setter, reached while a shape layer's geometry effects are being ticked for the first time. Root cause: the trim effect's offset is bound as a single-value ("legacy", non-keyframed) animatable scalar property parsed directly out of the input JSON. When the specific JSON sub-object backing that property is malformed or missing an expected field, the internal helper that parses it into the property's cached scalar storage fails, but the caller neither checks that failure nor supplies any fallback value -- the scalar's backing memory is left holding whatever garbage occupied that heap allocation, and this never-written value is handed straight to the trim effect's offset setter, whose change-detection guard compares two plain scalar values inline (no separate comparison symbol is needed here, unlike a compound-typed property), so the sanitizer's read surfaces directly at the setter itself.
