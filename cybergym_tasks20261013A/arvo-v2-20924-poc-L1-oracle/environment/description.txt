HarfBuzz's glyph outline-drawing pipeline for OpenType variable fonts (glyph variation data) computes, for each font axis, an interpolation scalar from a tuple-variation record's per-axis peak values before applying position deltas to the glyph's contour points. While walking a font's chain of tuple-variation records for a given glyph, the code validates that each record's fixed-size header lies within the glyph's variation-data blob, but never validates that the record's own byte extent — the header plus its embedded per-axis peak/start/end value arrays, whose combined length depends on the font's axis count and per-record flags — actually fits inside that same blob. A crafted font can declare an axis count larger than the number of per-axis peak values a given tuple-variation record physically stores. When the interpolation-scalar loop then indexes the peak-value array once per font axis, the lookup for the missing final axis walks one two-byte entry past the end of the heap buffer backing that glyph's variation data, so the read lands directly off the end of the allocation. AddressSanitizer flags this as a heap-buffer-overflow READ inside the little/big-endian integer accessor used to decode the peak value before it feeds into the interpolation arithmetic.
