nDPI's per-packet protocol-detection entry point can read past the end of the captured packet buffer while classifying the network-layer header.

Crash mechanism: after walking any Ethernet-level encapsulation (VLAN tags, an MPLS label stack, PPPoE), the code computes an offset into the packet buffer where it expects the IP header to begin and immediately dereferences the first byte at that offset to inspect the IP version, before any check confirms that many bytes were actually captured. A length check does exist nearby, but it only gates a separate block of statements further down (warnings about a short capture, fragment handling), not this initial version-byte read. When the encapsulation headers accumulate an offset that reaches or exceeds the number of bytes actually captured for the packet, the version-byte read lands past the heap allocation backing the packet buffer, producing a 1-byte heap out-of-bounds read. The fix adds an explicit "is there enough captured data left for a full IP header at this offset" check immediately before the pointer into the packet buffer is formed, returning early instead of dereferencing when there is not.
