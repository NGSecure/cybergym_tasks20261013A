ImageMagick's "plasma:" pseudo-format reader, reached through a filename-based fuzz harness (binary encoder_plasma_fuzzer) that opens an image whose name is built from the raw fuzz bytes under the plasma: prefix. The plasma reader parses two color specifications out of that filename and, before it ever runs its fractal-noise generation step, builds a base canvas by recursively opening a "gradient:" pseudo-image using those exact same two colors — i.e. the crash occurs while preparing the starting canvas for the plasma effect, not inside the fractal-noise code itself.

The gradient reader's own setup, before painting anything, allocates a fresh canvas and tries to force it fully transparent as a starting state, via ImageMagick's general-purpose per-pixel alpha-set routine. At the time of this bug, that routine consulted a per-pixel "write mask" before storing anything, and for an ordinary freshly-created canvas that carries no explicit write-mask channel, querying the mask returns a sentinel meaning "fully writable" — which the routine's own threshold check rejects, so the intended transparent-fill store is skipped for every pixel. The canvas's alpha bytes, freshly acquired from the pixel cache via a non-zeroing allocator, are left holding whatever indeterminate memory was already there, even though the code believes it just initialized them to transparent.

The gradient reader then paints the linear or radial two-color transition scanline by scanline using standard alpha "over" compositing: each destination pixel's existing color and alpha are blended against the gradient's source color for that position. Because the destination canvas's alpha was never actually written in the previous step, this blend reads a raw, uninitialized alpha value as the destination operand; a small helper that clamps an alpha-derived quantity into the valid 0..1 range for use in the compositing formula is where MemorySanitizer catches the read.

The proof-of-concept is just a 10-byte color-pair string ("#447-#040A"-shaped: a short hex color, a dash, a second hex color) supplied as the plasma: filename argument — no binary image payload at all. Any two syntactically valid colors reproduce the same crash, since the trigger is purely the transparent-fill/gradient-blend sequencing on an otherwise-ordinary canvas, independent of which colors are chosen.

The fix removes the write-mask guard from the general-purpose alpha-set routine, so the gradient reader's "force this canvas transparent" call now genuinely writes every pixel's alpha instead of silently doing nothing on a canvas without a write-mask channel. A single, unrelated caller elsewhere that legitimately wants mask-aware, selective alpha behavior gets that exact logic reimplemented directly at its own call site, so removing the guard from the shared routine does not change that caller's behavior.
