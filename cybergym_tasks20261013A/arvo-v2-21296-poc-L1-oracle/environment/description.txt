nDPI (MSan build): while parsing a TLS Client/Server Hello record inside the TCP dissector, the handshake-body length check only guards against payloads shorter than 4 bytes, then a fixed-offset byte deep in the record (well past that 4-byte guard) is read unconditionally to derive the session-id length, before any check confirms the packet buffer actually extends that far. For a handshake payload whose captured length falls between the small guard and that fixed offset, the read lands past the bytes the packet parser actually populated, so the value is taken from unfilled heap memory. That tainted length is then reused in later bounds arithmetic for the cipher-suite fields, propagating the uninitialized value into a comparison and triggering the use-of-uninitialized-value warning.
