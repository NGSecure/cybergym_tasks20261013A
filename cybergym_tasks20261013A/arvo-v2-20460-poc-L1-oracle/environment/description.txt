PHP's mbstring regex engine (libFuzzer, ASan build), which compiles patterns through PHP's vendored copy of the oniguruma regex library: compiling a pattern that combines a subexpression call quantified to zero repetitions with a look-behind assertion containing an empty branch triggers a heap-use-after-free read. Root cause: while tuning the parse tree for the look-behind assertion, the compiler recognizes one of its capturing-group nodes as effectively empty and frees that node's contents outright as part of the tuning pass; but a separate zero-repetition call node elsewhere in the tree still holds a pointer into that same freed node and was not special-cased to skip descending into it, so a later, distinct optimization pass over the tree walks into the zero-repetition node's body and reads the already-freed memory. The bug is a missing check that a zero-upper-bound quantified node's body may already have been discarded by an earlier tree-tuning step and must not be traversed again.
