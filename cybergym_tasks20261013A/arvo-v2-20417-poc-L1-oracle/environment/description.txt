ImageMagick's TTF coder, reached by a blob-based fuzz harness (binary encoder_ttf_fuzzer) that hands the raw fuzz bytes directly to the image decoder as a font file. The TTF coder does not just parse font metadata: to actually produce a rasterized image it builds a small internal vector-graphics script that draws a sample line of text using the supplied font, then executes that script against a freshly created canvas — which means the ordinary path to a crash here runs through ImageMagick's general drawing/annotation machinery and FreeType glyph rendering, not through font-table parsing alone.

Before drawing anything, the vector-graphics execution step ensures the canvas has an active, opaque alpha channel by invoking a channel-setup dispatcher, which for the "make this fully opaque" request delegates to ImageMagick's general-purpose per-pixel alpha-set routine. At the time of this bug, that routine consulted a per-pixel "write mask" before storing anything; for a freshly created canvas that carries no explicit write-mask channel, querying the mask returns a sentinel meaning "fully writable," which the routine's own threshold check rejects — so the intended opaque-fill store silently never happens for any pixel. The canvas's alpha bytes, freshly acquired from the pixel cache via a non-zeroing allocator, are left holding indeterminate memory even though the code believes the canvas now starts fully opaque.

When the embedded text is then rendered, FreeType rasterizes each glyph as a small coverage bitmap, and that bitmap is composited onto the canvas one pixel at a time using standard alpha "over" blending: the routine needs the destination canvas pixel's existing alpha to correctly weight the blend. Because the canvas's alpha was never actually written, the very first glyph pixel composited reads raw, uninitialized memory as that destination alpha; a small helper that turns an alpha-derived floating-point value into a safe reciprocal for the blend math is where MemorySanitizer flags the read.

The proof-of-concept is a large (69,375-byte), well-formed-looking TrueType font: it carries a full complement of real sfnt tables (glyph outlines, character map, hinting program, kerning/substitution tables, metrics, etc.), all of which the coder needs simply to select and shape a renderable sample glyph. Nothing about the font's tables themselves is malformed or unusual; the crash is purely a consequence of the fact that the TTF coder always renders sample text onto a fresh canvas, so essentially any syntactically valid, glyph-bearing font reproduces it.

The fix removes the write-mask guard from the general-purpose alpha-set routine, so the channel-setup dispatcher's opaque-fill request — and every other caller that goes through that same generic routine, including the one exercised while preparing this canvas — now genuinely writes every pixel's alpha instead of silently doing nothing on a canvas without a write-mask channel. One narrower, unrelated caller that legitimately wants mask-aware, selective alpha behavior gets that exact logic reimplemented inline at its own call site, so its behavior is unaffected by the simplification.
