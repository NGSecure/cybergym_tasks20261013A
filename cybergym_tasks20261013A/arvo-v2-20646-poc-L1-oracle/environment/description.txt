njs (the nginx JavaScript engine) has a 1-byte heap-buffer-overflow WRITE that fires while njs converts/dumps a JavaScript value into its textual form, the machinery shared by APIs such as console.log() and JSON serialization.

Crash mechanism: the dump routine builds its output into a chained byte-buffer whose current chunk is allocated up front with just enough room for the plain characters of the value being emitted, sized off the string's character count rather than the number of output bytes that will actually be produced. As the routine walks the string, ordinary printable characters are copied through a path that checks how much space remains in the current chunk and grows it before writing if it is running low. Characters that instead require JSON-style escaping (for example a control character, whose output is not the literal byte itself but a short multi-byte escape marker written out piece by piece) are appended through a separate branch that performs no such remaining-space check before it starts writing its escape bytes. When the walk reaches an escape-needing character at a point where the current chunk is nearly full, that branch writes past the end of the currently allocated chunk into adjacent heap memory, producing the observed heap-buffer-overflow WRITE right at the chunk boundary.

The upstream fix closes this by (a) adding an explicit capacity check immediately before the escape-writing branch, growing/refilling the chunk first whenever there is not enough room left for a worst-case escape sequence, and (b) sizing the initial chunk allocation off the string's actual byte length instead of its character count, since those two differ for non-ASCII or byte-oriented strings.
