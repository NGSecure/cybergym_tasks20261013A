Decoding a crafted Apple PICT (Macintosh QuickDraw picture) image through GraphicsMagick's PICT coder can trigger a small heap-buffer-overflow read: for a repeated ("compressed") run in the scanline's byte-oriented, PackBits-like decompression scheme, a single source byte is read from a temporary per-scanline buffer and, for sub-byte pixel depths, unpacked bit-by-bit by a small helper routine before being replicated into the output. That buffer is sized to one of a couple of fixed capacities chosen from the scanline's byte width rather than to any exact bound on how far the decompressor can advance through it, and neither the run decoder nor the helper re-checks that the source position it is about to read still lies inside whichever fixed-capacity chunk was allocated, so a crafted PICT file can drive the run decoder's bookkeeping a short distance past the end of that heap allocation before this single-byte read occurs.
