nDPI's FIX (Financial Information eXchange) protocol detector runs against every TCP flow as part of application-layer classification: as soon as a flow is recognized as carrying a TCP payload, the detector immediately inspects the very first two bytes of that payload, looking for the "8=" prefix with which every legitimate FIX message begins, in order to decide whether to keep classifying the flow as FIX. The condition that gates this inspection only confirms that the flow is over TCP; it never confirms that the payload actually contains at least two bytes before those two bytes are compared. A TCP packet that carries an empty payload, or only a single payload byte, still reaches this signature probe, and the second half of the two-byte comparison dereferences one byte past the end of the allocated (very small) payload buffer. This produces a 1-byte heap-buffer-overflow read that happens directly inside the detector's own comparison code, on the very first bytes it ever looks at for that flow. It is not the result of any length-driven offset arithmetic or an iterative header-walking loop, and it is unrelated to the parsing logic of any other application-layer detector in the same codebase — the fix is simply a minimum-payload-length guard added before the two-byte prefix is touched at all.
