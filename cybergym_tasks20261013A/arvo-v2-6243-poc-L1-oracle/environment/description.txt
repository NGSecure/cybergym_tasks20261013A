ImageMagick (MSan build): acquiring a new image with a crop/extract geometry option parses the geometry string into a local rectangle whose fields are only set for the components actually present in the string, not zeroed first; the caller then unconditionally copies both offset components into the image's page geometry whenever either one was supplied, so a string giving just one offset leaves the other as stack garbage. Reading a LABEL image whose label text is later expanded through the percent-escape property interpreter formats this page geometry, and the read of the still-unset offset surfaces as a use-of-uninitialized-value warning far from the routine that actually created the bad value.
