harfbuzz hb-subset (ASan build): while subsetting a font's embedded color-bitmap ('sbix') table, harfbuzz derives each retained glyph's raw image byte range from the difference between two consecutive entries of a per-strike table of image-data offsets, checking only that the two offsets are strictly increasing and that the resulting range is larger than a small fixed glyph header -- it never checks that the offset marking the end of a glyph's image data actually falls within the true byte length of the color-bitmap table being subset. A crafted end offset that overshoots the table's real size by only a small amount therefore still satisfies both existing checks, so the code proceeds to copy exactly that (too-large) byte count out of the source image data through a generic length-driven buffer-copy helper that trusts the caller-supplied length outright, reading one byte past the end of the heap allocation backing the color-bitmap table.
