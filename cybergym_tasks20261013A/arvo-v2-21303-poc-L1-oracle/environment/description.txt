Fraunhofer FDK AAC's MPEG-D Dynamic Range Control (uniDrcConfig) parser reads an uninitialized stack value while parsing the equalizer (EQ) instructions sub-block of a decoder-config bitstream, flagged by MemorySanitizer through the aacDecoder_ConfigRaw entry point.

Root cause: while walking the per-channel EQ-group assignment list, the parser keeps a small fixed-size scratch buffer of per-channel group identifiers so that, for each newly processed channel, it can check whether that channel's identifier repeats one already seen in an earlier iteration of the same loop. That scratch buffer is (re-)declared fresh on every iteration of the very loop whose earlier iterations it is meant to remember, so as soon as more than one channel is processed, the duplicate-group check compares the just-read identifier against buffer slots that were never written during the current iteration — an uninitialized-stack read rather than a real value comparison. This read does not corrupt memory or crash by itself; it is MemorySanitizer's instrumentation that surfaces the undefined value. In a non-sanitized build the resulting nondeterministic "duplicate" decision could silently skew how many independent EQ channel groups the decoder believes are present, which in turn sizes the downstream filter-cascade and subband-gain parsing that follows in the same configuration record.

The correct fix hoists that scratch buffer's declaration out of the per-channel loop into the enclosing function's top-level locals, so a single buffer persists and is validly written across iterations instead of being reallocated (and left uninitialized) on every pass.
