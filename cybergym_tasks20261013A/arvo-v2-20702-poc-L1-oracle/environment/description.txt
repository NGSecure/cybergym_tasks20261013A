file (libmagic) magic_fuzzer target (MSan build): evaluating an "indirect" magic rule recurses into a nested softmagic match at a different offset inside the input, first saving the current output-text accumulator (its pointer, length, and read offset) onto a heap-allocated stack frame so the recursive match can start with a clean, empty buffer. The save routine copies over the saved buffer pointer and the saved offset but never writes the frame's saved-length field, so that field is left holding whatever stale heap bytes happened to be there at allocation time. Once the nested match returns, the frame is popped and that never-initialized length field is copied straight back into the live accumulator state as its current buffer length. A later text-emitting call that formats the outer match's own description then uses this restored length as one side of an output-size cap comparison, so the comparison consumes uninitialized memory and MemorySanitizer reports a use-of-uninitialized-value.
