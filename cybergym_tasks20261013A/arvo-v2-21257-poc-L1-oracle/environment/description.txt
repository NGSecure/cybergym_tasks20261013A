nDPI's SSH protocol detector, once a flow has already been classified as SSH and a later packet in that same connection is being examined during the key-exchange phase, builds an internal comparison buffer out of several fields taken from that packet's payload. One of the first fields it pulls out is a 4-byte length value, read directly from a fixed byte offset near the start of the payload, which is then used to keep assembling the rest of the buffer. Before this specific 4-byte read, nothing verifies that the payload actually extends far enough past that fixed offset to hold a complete 4-byte value — only later, length-derived offsets computed further down in the same routine are checked against the payload's size, not this first, hardcoded one. An SSH-classified payload whose total length is smaller than the fixed offset plus four bytes still reaches this read, producing a 4-byte heap-buffer-overflow read that runs past the end of the allocated packet buffer. The overflow occurs on the very first field the routine extracts, at a fixed offset from the start of the payload, rather than as part of any iterative, length-chained walk through the buffer, and it is unrelated to the DNS-, FIX-, or Yahoo-Messenger-related parsing paths in the same codebase.
