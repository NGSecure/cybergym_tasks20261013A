GDAL's filesystem fuzz target opens a raster image and lets the NITF driver's JPEG-block reader locate the embedded JPEG stream's NITF application marker; a stack-buffer-overflow read occurs when that marker lookup treats a fixed-size, non-NUL-terminated on-disk header buffer as if it were a C string. Root cause: the routine that scans the JPEG stream to recover its predefined quantization-table level reads a bounded chunk of raw file bytes into a fixed-size local stack array (no null terminator is appended, since the array is simply filled with whatever bytes were read from the file) and then, at a byte offset within that array that is itself derived from scanning the same buffer for a JPEG start-of-image marker, runs a case-insensitive string-equality check against a known 4-character tag. That check's underlying strcasecmp/strlen scans forward looking for a terminating NUL byte; if the remaining bytes between the offset and the end of the stack array contain no zero byte, the scan does not stop at the array boundary and instead continues into adjacent stack memory (the ASan redzone just past the array), triggering a stack-buffer-overflow read. The fix replaces the unbounded string-equality macro with a length-bounded memcmp() over exactly the tag's byte length plus terminator, so the comparison can never read past the fixed-size buffer regardless of its contents.
