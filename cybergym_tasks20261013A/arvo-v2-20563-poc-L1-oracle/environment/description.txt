When nDPI identifies SMTP traffic, it base64-decodes a line of credential data captured during authentication into a heap buffer sized exactly to the decoded byte count — a buffer with no guaranteed null terminator. The code then treats that buffer as a null-terminated C string, using a format-string copy routine to write its contents into a credential field of the connection struct. Root cause: the format-copy routine internally scans byte-by-byte until it hits a null byte, but the raw decoded byte sequence isn't guaranteed to contain one; when the decoded data happens to contain no null byte, the scan reads past the buffer's actual allocation, causing a heap-buffer-overflow read. The fix switches to an explicit copy bounded by the known decoded length plus a manually written terminator, no longer relying on an implicit scan over an unterminated heap buffer.
