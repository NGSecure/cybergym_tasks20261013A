A bug in wireshark (ASan heap-buffer-overflow, 1-byte READ) occurs while dissecting an OSI/ISO CLNP-family PDU that carries a binary NSAP address: a helper that formats such an address for display first prints a fixed set of leading octets, and then, only when the address's encoded length matches one specific "RFC 1237 full-area plus one extra octet" variant, appends one more octet by indexing the same address byte array with a hardcoded literal offset instead of computing the offset that immediately follows the bytes it just printed. That literal offset is far larger than the correct next-octet position, so it lands well past the end of the (much shorter) address buffer the caller actually supplied, reading 1 stray byte out of the adjacent heap redzone.
