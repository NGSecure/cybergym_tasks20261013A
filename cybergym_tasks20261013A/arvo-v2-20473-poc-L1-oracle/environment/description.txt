After htslib opens a BAM/SAM-family file, the htsFile struct uses a union to hold the actual underlying handle, and a dedicated flag decides whether that union should be treated as a compressed-layer handle or a plain generic file handle: for BAM/binary formats, htslib always opens through the same compression-layer interface and sets that flag, regardless of whether the file's bytes are actually bgzf-compressed (even an uncompressed "naked" BAM), so the union always holds a compression-layer handle pointer in that case. But an internal routine that builds header information and needs to peek at the next byte to detect end-of-header instead decides which union member/interface to use based on a different field — one describing whether the file's bytes are bgzf-compressed at the byte level — rather than the flag that actually determines what type of pointer the union holds. When a naked (uncompressed) BAM file is opened, the two disagree: the flag is set (union holds a compression-layer handle), but the byte-level format probe says non-bgzf, so the code mistakenly takes the "non-bgzf" branch and passes the compression-layer handle pointer to a generic "peek next byte" routine as if it were a generic file handle. That routine reads a buffer-start-pointer field at the offset expected for the generic-handle layout, but the same memory is actually a compression-layer handle struct, so it reads an unrelated field value there and misinterprets it as an invalid wild pointer; a subsequent memory copy through that wild pointer then crashes on the unmapped address. The fix makes these "which union member/branch to use" decisions consistently check the flag that actually indicates the union's real type, instead of substituting the byte-level compression-format probe for it, eliminating this type confusion; a separate spot in the index-building path that had inverted the same mistake (using the type flag to judge byte-level bgzf compression) is changed back to checking the format probe, so the two differently-meaning fields each return to their own purpose instead of standing in for each other.
