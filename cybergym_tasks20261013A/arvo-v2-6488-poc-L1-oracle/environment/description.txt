ImageMagick (ASan build): when DrawImage() renders an MVG 'path' drawing primitive whose data includes a quadratic/smooth-quadratic-Bezier-style curve segment, the routine that walks the interpolated curve and emits its sampled coordinates one point at a time -- past the point where the curve's initial control points were already stored into the same buffer -- keeps appending to a fixed-capacity geometry buffer that was sized too small for a curve-heavy path, so partway through this per-point sampling pass a single-field write lands past the end of that heap allocation (heap-buffer-overflow write). This is the same undersized shared buffer and the same curve-command family responsible for a sibling overflow that instead happens earlier, during the bulk write of the curve's initial control points before any per-point sampling begins.
