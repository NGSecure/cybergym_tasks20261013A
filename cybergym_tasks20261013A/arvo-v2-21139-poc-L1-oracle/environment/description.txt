htslib's VCF text parser (ASan hts_open_fuzzer build): a wild-address write crash (SIGSEGV) occurs while finishing per-sample FORMAT-field parsing for a variant record. Root cause: the routine that lays out a scratch buffer to hold every sample's FORMAT values sizes it by multiplying the record's declared sample count by a per-field byte width using ordinary word-width-limited integer arithmetic, and later derives each individual sample's byte offset into that same buffer with the identical sample-count-times-width multiplication. When a malformed record declares an unusually large sample count together with a large per-field width, this multiplication silently overflows/wraps, so the buffer that actually gets allocated ends up far smaller than what the per-sample offset math assumes for later samples. The fault surfaces in the tail step that back-fills a default "missing" placeholder for samples whose trailing FORMAT columns were left implicit: it computes a pointer into the scratch buffer from the (already-wrapped) offset for one such sample and writes a single placeholder value through it, landing on an address well outside the real allocation and crashing with a wild-pointer write.
