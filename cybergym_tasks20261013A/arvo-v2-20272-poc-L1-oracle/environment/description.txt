Decoding a crafted Apple PICT (Macintosh QuickDraw picture) image through GraphicsMagick's PICT coder can trigger a heap-buffer-overflow read: for a literal ("uncompressed") run in the scanline's byte-oriented, PackBits-like decompression scheme, an attacker-controlled control byte determines how many following bytes are copied straight out of a temporary per-scanline buffer into the output pixel buffer. That buffer is sized to one of a couple of fixed capacities chosen from the scanline's byte width rather than to any exact bound on the literal run lengths the decompressor can encounter, and the copy is never re-checked against how much of that fixed-capacity chunk actually remains, so a crafted PICT file can select a run length that carries the copy a short distance past the end of the heap allocation.
