ImageMagick's JPEG decoder suffers a stack-buffer-overflow read while parsing an ICC color-profile marker embedded in a crafted JPEG file. Root cause: the profile-marker handler copies a small, fixed number of raw bytes from the marker payload into a fixed-size local stack buffer that is meant to hold a short identifying tag, but never appends a NUL terminator afterward. That tag buffer is then handed to a case-insensitive string-comparison routine to check it against a known profile-identifier string; the routine assumes both of its arguments are NUL-terminated C strings and scans forward looking for a terminating zero byte. Because the buffer was sized to hold exactly the raw bytes with no room for (or insertion of) a terminator, and none of the copied bytes happen to be zero, the scan runs past the end of the undersized buffer into adjacent stack memory (and can reach the stack redzone) before it ever finds a zero byte, producing an out-of-bounds read. The fix widens the buffer by one byte and explicitly writes a NUL terminator right after the raw bytes are copied in, so the comparison can never read beyond the buffer's valid contents.
