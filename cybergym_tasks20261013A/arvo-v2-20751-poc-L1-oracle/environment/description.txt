GDAL's GRIB2 raster driver (ASan build, honggfuzz target) suffers a heap out-of-bounds write while copying decoded grid-cell values into the raster's in-memory data array. Root cause: when the grid definition section of the GRIB2 message describes a large row/column extent, the routine that lays out decoded values into their final (row, column) position derives each cell's flat array offset from the grid's declared width using a mix of signed and unsigned 32-bit integer arithmetic. For grid dimensions whose derived offset cannot be represented within the signed 32-bit range used to hold it, the computation wraps around instead of producing a value clamped to the array actually allocated for the grid, and the resulting offset is never validated against the buffer's real size before being used. The subsequent store of the decoded value at that offset therefore lands far outside the heap allocation backing the grid array, corrupting unrelated heap memory and triggering an AddressSanitizer wild-address SIGSEGV write (crash type: UNKNOWN WRITE) deep in the GRIB2 grid-data unpacking path invoked while GDAL rasterizes a block of the opened GRIB dataset.
