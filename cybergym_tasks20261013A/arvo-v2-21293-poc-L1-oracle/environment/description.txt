stb_image's PNG loader (MemorySanitizer build under the stb_png_read_fuzzer harness) reports a use-of-uninitialized-value read while unfiltering a decompressed scanline into the final pixel buffer: for sub-byte bit-depth images, the row-unpacking code computes a write/read offset into the freshly zlib-decompressed output by assuming the packed row byte count never exceeds the image's pixel width, an invariant that is only checked via a debug-only assertion compiled out of the fuzz build. A crafted PNG whose declared width/bit-depth combination violates that assumption drives the offset calculation out of sync with how many bytes the Huffman/zlib inflate step actually wrote for that row, so the unfiltering logic ends up reading bytes from a region of the freshly allocated decompression buffer that inflate never touched, i.e. uninitialized heap memory, which MemorySanitizer flags before any wrong value is used or output.
