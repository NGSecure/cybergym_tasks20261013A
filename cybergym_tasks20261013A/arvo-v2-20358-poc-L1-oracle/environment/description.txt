jbig2dec's generic-region arithmetic decoder (ASan heap-buffer-overflow read of 1 byte) mis-clamps the row boundary that gates its bounds-check-free fast-path pixel accessors: the boundary is derived from the region's signed adaptive-template pixel-offset fields via a comparison between an unsigned local variable and a signed value that can legitimately be negative, so a negative offset is implicitly reinterpreted as an enormous unsigned number and gets assigned straight into the boundary, which then wraps again on the following subtraction and ends up sitting only a few pixels from the image's last column instead of a full safety margin away; pixels decoded near that column then go through the fast accessor that always reads one extra byte ahead to gather enough bits regardless of how many are actually needed, landing one byte past the end of the image's final scanline allocation.
