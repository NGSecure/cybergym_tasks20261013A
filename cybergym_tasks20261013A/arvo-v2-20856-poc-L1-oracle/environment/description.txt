nDPI's Yahoo Messenger protocol detector, invoked while classifying a TCP flow, walks the packet payload as a sequence of consecutive protocol message headers: it reads a length field from the current header to compute the byte offset where the next header should begin, then inspects that next header's leading magic-signature bytes to decide whether to keep looping. The offset arithmetic is checked against the total payload length only loosely (the raw offset value itself must stay within bounds), but nothing verifies that enough trailing bytes actually remain in the buffer to hold a complete header structure — including its signature field — starting at that offset. A payload whose embedded length value lands the computed next-header offset close enough to the end of the buffer causes the loop to keep iterating and immediately dereference/compare bytes at that offset as if a full header were present there. This reads a handful of bytes beyond the allocated payload buffer, producing a heap-buffer-overflow read detected by ASan inside the C library comparison routine used for the signature check. The crash is purely a missing remaining-length check before a fixed-size struct-shaped read/compare on attacker-controlled length-driven parsing; it is not related to allocation size, integer overflow in the length field itself, or any other protocol path in the same codebase.
