Decoding a crafted WordPerfect Graphics (WPG) image through GraphicsMagick's WPG coder can trigger a heap-buffer-overflow write: because the coder reuses one in-memory image object across a file's whole sequence of embedded blocks, an earlier block can hand off to an unrelated bitmap decoder that sets up a small backing pixel-cache sized only for its own tiny width and height, and when a later block in the same file then declares a much larger bitmap width and height taken straight from that block's own header fields, the row-unpacking routine's first attempt to write a decoded scanline (or, for palette-depth pixels, per-pixel palette-index values) into that still-undersized cache fails but is not treated as fatal, so it falls through into its normal remaining-rows recovery pass and a later such write for a row near the end of the larger declared image lands past the end of the small heap allocation still backing it.
