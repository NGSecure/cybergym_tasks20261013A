nDPI's IRC protocol classifier, while scanning a reassembled TCP line to recognize known IRC chat/file-transfer command keywords, walks the line buffer at increasing offsets and compares a fixed-length substring against each candidate keyword; one of these keyword comparisons uses a fixed comparison length without first checking that enough bytes remain between the current scan offset and the end of the line buffer. When the scanned line is shorter than that offset plus the comparison length, the fixed-length byte compare reads past the end of the heap-allocated line/packet buffer, which AddressSanitizer reports as a small heap-buffer-overflow read inside the C library's memory-compare routine, called from the IRC classifier, which is itself reached from nDPI's generic TCP-flow protocol-detection dispatch on every packet the fuzz harness feeds in.
